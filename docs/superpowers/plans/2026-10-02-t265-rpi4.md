# T265 RPi4 VIO Implementation Plan

Goal: Run Granite stereo and mono VIO from the attached T265 on RPi4.
Authorization: The user requests all implementation, tests, debugging, and fixes without further questions.
Architecture: Reuse RsT265Device and Granite optical flow / inertial estimator. Add headless examples and optional RealSense targets. Preserve default GUI targets.
Constraints: 30 Hz sensor input; half images 424x400; all IMU samples retained; maximum build concurrency 2 on RPi4. Existing checkout is clean; work on feature/t265-rpi4-vio and edit an isolated local source copy.

- [x] Calibration and image tests: compare projected rays before/after resize, distortion unchanged, extrinsics unchanged, stereo pairs removed in mono, camera 2 reindexed to 0, padded stride and uint8/uint16 image conversion.
- [x] Restore device header, export selected/scaled calibration, stop pipeline before queue sentinels, interpolate accelerometer at gyro timestamps using existing logic. Use RealSense indexed fisheye access and OpenCV INTER_AREA.
- [x] Add headless stereo/mono targets, duration, signals, capture-only diagnostics, trajectory CSV and frame-rate/lag metrics. Use existing vio_enforce_realtime; never block the SDK on image delivery.
- [x] Fix build compatibility using TBB config package, optional GUI dependencies, and ARM-compatible compiler flags. Configure/build, then run ctest.
- [x] Live test full/half stereo and left/right mono. Measure states/sec, lag and input drops. Tune example configuration only when measurements justify it. Report limited motion test honestly.
- [x] Review final diff and test results, preserve changes on RPi4, document commands and limitations, capture episode.

Review focus: No device / wrong device, invalid arguments, missing image or exposure metadata, early shutdown, slow consumer, stationary mono observability.

Scope update: Support mono VO, mono VIO, stereo VO, stereo VIO. Add a separate MonoVioEstimator selected by factory for one-camera inertial input. Preserve original mono VO behavior and robustness. Use existing KeypointVoEstimator for visual bootstrap, then solve gyro bias, scale, gravity and velocities using Granite preintegration. Reject stationary / constant-velocity / pure-rotation scale ambiguity. Transfer the metric map into the existing sliding-window IMU backend. Tests must cover non-unit scale, tilted gravity, nonzero camera-IMU translation, gyro bias, and degenerate motion. VINS-Mono initialization is an algorithm reference; implement equations independently with Granite APIs.
Build baseline issue: keypoint_vo.h uses std::optional without including <optional>; add only that header.

Validation limitation: attached camera is stationary with nearly uniform dark images. Physical moving-scene mono metric initialization/accuracy and textured-scene real-time speed require a future capture. Intermittent sensor image stalls are detected and terminate cleanly; startup reset is not claimed to eliminate every stall. Local changes are committed on feature/t265-rpi4-vio with origin git@github.com:Keunmo/granite.git; no push or merge requested.
