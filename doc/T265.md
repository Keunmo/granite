# Live T265 odometry on Raspberry Pi 4

The examples use the T265 fisheye images and raw accelerometer/gyroscope streams. They estimate poses in Granite; they do not use the T265 firmware pose stream.

## Build

Install the normal Granite dependencies and librealsense2 (tested with 2.53.1). Initialize the repository submodules before building. Headless builds omit Pangolin and the GUI applications. On RPi4 use one compiler job to limit peak memory:

```sh
cmake -S . -B build-rpi4 \
  -DCMAKE_BUILD_TYPE=Release \
  -DGRANITE_BUILD_GUI=OFF \
  -DGRANITE_BUILD_REALSENSE=ON \
  -DUSE_OPENMP=OFF
cmake --build build-rpi4 --target granite_rs_t265_mono_vo \
  granite_rs_t265_mono_vio granite_rs_t265_vo granite_rs_t265_vio -j1
```

## Four modes

```sh
# Left fisheye, original Granite monocular VO
./build-rpi4/granite_rs_t265_mono_vo --resize-half
# Left fisheye, monocular metric VIO
./build-rpi4/granite_rs_t265_mono_vio --resize-half
# Both fisheyes, stereo VO
./build-rpi4/granite_rs_t265_vo --resize-half
# Both fisheyes, stereo VIO
./build-rpi4/granite_rs_t265_vio --resize-half
```

`--mono-camera 2` selects the right fisheye for either monocular example. `--mono-camera 0` selects stereo. The general runner also accepts `--use-imu true` or `--use-imu false`.

`--resize-half` downsamples 848 × 800 images to 424 × 400 using area averaging. It scales focal lengths by 0.5 and transforms principal points as `(c + 0.5) * 0.5 - 0.5`, matching the pixel centers used by the resampling. Fisheye distortion and camera-to-IMU extrinsics remain valid. Without the flag, native resolution is used.

## Monocular VIO initialization

Monocular VO supplies the visual bootstrap, retaining Granite's existing keyframe selection, infinity landmarks and scale robustness behavior. A separate visual-inertial alignment estimates metric scale, gravity direction, velocity and gyroscope bias from the visual trajectory and IMU preintegration. The transferred map is rescaled and passed to the existing inertial optimization backend.

Metric initialization needs translation with changing acceleration and sufficient visual parallax. Move the camera through a short smooth motion; a stationary camera, pure rotation or constant velocity cannot determine scale. Until initialization succeeds the example reports `metric_initialized=false` and emits no metric poses. It prints `MONO_VIO_INITIALIZED` when alignment succeeds. Gravity is aligned to the estimator world frame; world position and yaw remain arbitrary. Mono VO retains its arbitrary scale.

The alignment was independently implemented using Granite preintegration and the standard visual-inertial alignment equations. The [VINS-Mono initialization implementation](https://github.com/HKUST-Aerial-Robotics/VINS-Mono/blob/master/vins_estimator/src/initial/initial_aligment.cpp) was consulted as an algorithm reference; its source was not copied.

## Capture, logging and performance

```sh
./build-rpi4/granite_rs_t265_mono_vio --resize-half --duration 30 \
  --num-threads 3 --trajectory /tmp/mono-vio.csv --save-calib /tmp/t265.json
./build-rpi4/granite_rs_t265_vio --resize-half --capture-only --duration 10
```

Use `--help` for all options. `--duration 0` runs until Ctrl-C. `--exposure 0` enables automatic exposure; positive values set exposure in milliseconds. `--config-path` loads a Granite JSON configuration after the example defaults. The example defaults enable realtime processing, five keyframes and four optimizer iterations.

Image capture has a bounded queue and may drop stale frames when processing falls behind. IMU samples are retained. Per-second statistics report received image rate, output state rate, image drops, IMU queue depth and newest captured image timestamp minus output timestamp in milliseconds (`lag_ms`). This lag measures backlog relative to the current stream, not physical sensor latency. `--skip-frames N` intentionally processes every Nth image and is separate from half resolution.

Trajectory CSV contains timestamp, position, quaternion and velocity. Stationary mono VIO capture can exit successfully with zero states while awaiting observable motion; that is not evidence of successful metric initialization.

## Tests

`test_t265_image` verifies downsampling, image stride, monocular camera selection and calibration projection. `test_mono_vio_alignment` verifies metric scale, gravity, gyroscope bias, camera/IMU lever arm and unobservable-input rejection. `test_mono_vio` drives the estimator with synthetic temporal image observations and IMU, checking metric motion, finite landmarks, stationary initialization deferral, initial accelerometer bias and a small backend keyframe window.
